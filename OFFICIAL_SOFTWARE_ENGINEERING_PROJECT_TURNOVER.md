## II. PURPOSE OF PROJECT TURNOVER

The Software Engineering Project Turnover serves as the official transfer of project assets, technical documentation, source code, repositories, software artifacts, manuals, databases, and related deliverables from the student proponents to Mabini Colleges, Inc.

The objectives of this turnover are:

1. To preserve software engineering outputs as institutional academic assets
2. To establish a permanent Software Engineering Project Repository for future instructional, accreditation, research, extension, and curriculum enhancement purposes
3. To ensure that future students may study, analyze, maintain, enhance, migrate, or redevelop previously completed systems
4. To maintain institutional continuity and knowledge transfer within the Software Engineering program
5. To ensure compliance with software engineering documentation standards and professional development practices

## IV. MANDATORY TURNOVER OF SOURCE CODE AND REPOSITORIES

### Policy Statement

Submission of the operational software system alone shall **NOT** constitute compliance with project turnover requirements.

The College specifically requires the turnover of:

- Complete Source Code
- Database Structures
- Development Environment Configurations
- Dependency Files
- Framework Configurations
- Repository Structures
- Technical Documentation

This requirement exists because software engineering education is not limited to the final software product.

The educational value of a software project includes:

- Requirements Engineering
- Software Architecture
- Design Decisions
- Development Methodologies
- Coding Practices
- Testing Procedures
- Configuration Management
- Documentation Standards

Without access to these artifacts, future students, faculty members, evaluators, accrediting bodies, and researchers would be unable to properly analyze the software engineering processes involved in the project.

## V. KNOWLEDGE TRANSFER REQUIREMENT

All submitted projects shall be prepared in such a manner that another Software Engineering student, faculty member, researcher, or evaluator can independently:

- Understand the problem being solved

- Understand the algorithms utilized
- Understand the framework implementation
- Install the software

- Extend the software

## OFFICIAL ZIP FILE NAMING CONVENTION

To ensure proper archiving, retrieval, accreditation review, repository management, and future reference by succeeding Software Engineering students, all groups shall strictly follow the prescribed file naming conventions.

### A. MASTER PROJECT TURNOVER ZIP FILE

Each group shall submit **ONE (1) MASTER ZIP FILE** containing all required project artifacts.

**Format:**
```
SE2026_[SYSTEMNAME]_[GROUPNAME].zip
```

**Examples:**
```
SE2026_InventoryManagementSystem_GroupAlpha.zip
SE2026_EBarangayManagementSystem_Group3.zip
SE2026_StudentClearanceMonitoringSystem_TeamInnovators.zip
```
